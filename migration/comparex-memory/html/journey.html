Life of an issue

Follow one real-looking problem, a timestamp precision mismatch on sales.dbo.orders.created_at, from the moment Comparex finds it to the moment memory helps fix the next one. Click a stop, or use the buttons and your arrow keys.

Grey rings are things the existing pipeline does. Amber rings are things memory does.


      

    

  


  

    
Why this is a loop, not a line

    

      
Steps 1 to 7 happen for every issue. Step 8 is where the payoff shows up: the next issue with the same structure gets a memory file that already knows what worked. Every new fix, pass or fail, feeds back into step 7, so recommendations keep improving without anyone curating them.

      
Memory runs this as a repeating ingest cycle (every few minutes, or from the scheduler). Each cycle only looks at files and commits that changed since the last one, so running it twice changes nothing.
