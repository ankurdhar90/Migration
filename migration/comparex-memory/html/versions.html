Two versions, one after the other

Version 1 keeps memory in a SQLite file on the machine that runs the pipeline. Version 2 adds Snowflake as a shared, long-term copy. Version 2 is version 1 plus one phase, so starting small costs nothing.

Upgrading never redoes work

Version 1 already keeps what version 2 needs: every table has an updated_at column (used to find new rows to push) and an empty sync_state table (remembers how far each sync got). So adding Snowflake later needs no database migration and no rebuild.

How sync works, in short: after each cycle, rows changed since the last push go into a temporary stage table in Snowflake, then a MERGE inserts new rows and updates rows only when the incoming copy is newer. A new machine pulls rows newer than its own and rebuilds its text index.
