LIQ migration · comprehensive approach

How the tier-1 migration is performed

This is everything agreed so far, in one place. Snowflake takes over the Liquidity tier-1 interface tables, one switch group at a time, by renaming the Snowflake-fed table into the original name. Everything after tier-1 stays on SQL Server, unchanged. Parity with legacy is proven in UAT against production before production switches, because once a table switches, legacy stops feeding it.

  • Only tier-1 changes. Deposit enrichment, the other tier-2 processes and the reports aren't touched and can't be repointed.
  • Same names, real tables. Tier-2 keeps reading Transaction.TBLDeposits. No synonyms.
  • Designed per table. Switched in groups, so each tier-2 process reads one source.
  • A one-way flow after the switch. Nothing flows from TDM_CDM into the legacy table any more. It's frozen as the rollback point.
  • UAT is the only rehearsal. It's production-like, gets the same sources and holds full history. Production is the baseline.
  • Liquidity stays on SQL Server for now. A parallel Liquidity database is a later phase.

Where we are today

Two three-layer platforms fed by the same sources. In UAT, DMVA copies Snowflake's tier-1 into the SnowIn schemas, and three reconciliations run every day. Production runs the legacy path only.

Load mechanicsControl-M runs a wrapper, which runs dtexec with the SQL Server config. Each package deletes the business date in tier-1, runs the LIQ proc through the alias, and streams the result set into tier-1.
KeysKeys are created in each platform's CDM and differ between them. Tier-1 rows get identity values when inserted. Tier-2 joins on codes, not IDs.
TimingSnowflake output and the DMVA copy land earlier than the legacy path, because SSIS is the slow step.
OwnershipThe project team owns Config and can change anything. Any repoint changes the SSIS config and the alias together.

Script for Transaction.TBLDeposits

-- T-1 evening, after the D-1 legacy load and tier-2 have finished
TRUNCATE TABLE SnowInTransactions.TBLDeposits;
SET IDENTITY_INSERT SnowInTransactions.TBLDeposits ON;
INSERT INTO SnowInTransactions.TBLDeposits (<all columns>)
SELECT <all columns> FROM Transaction.TBLDeposits;          -- every business date up to D-1
SET IDENTITY_INSERT SnowInTransactions.TBLDeposits OFF;
DBCC CHECKIDENT ('SnowInTransactions.TBLDeposits', RESEED, <max legacy id>);
-- verify: counts and checksums per business date match Transaction.TBLDeposits

BEGIN TRAN;
  ALTER SCHEMA LegacyTransactions TRANSFER Transaction.TBLDeposits;       -- legacy frozen at D-1
  ALTER SCHEMA Transaction        TRANSFER SnowInTransactions.TBLDeposits;
COMMIT;
-- reapply grants on Transaction.TBLDeposits (a schema transfer drops them)
-- Control-M: disable the TBLDeposits SSIS job; DMVA target -> Transaction.TBLDeposits;
--            tier-2 in-condition -> DMVA load + gate

-- ROLLBACK, inside the window only
BEGIN TRAN;
  ALTER SCHEMA SnowInTransactions TRANSFER Transaction.TBLDeposits;
  ALTER SCHEMA Transaction        TRANSFER LegacyTransactions.TBLDeposits;
COMMIT;
-- reapply grants; re-enable SSIS; run the legacy load for every live date from T; rerun tier-2

The daily run after the switch

Where the evidence comes from

Parity with legacy can only be proven before the production switch. Once a group switches, legacy no longer produces that data in production, so there is nothing to compare against there. All the parity evidence has to come from UAT against production, including a month-end and a quarter-end, before the production switch.

Rollback, with no legacy flow running

The legacy table is frozen at D-1, so renaming back alone would leave tier-2 without the live dates. Every rollback has a catch-up step, and the window is time-boxed.

What this replaces from earlier pages

  • The alias-based in-and-out step and thin LIQ procedures are no longer needed, because UAT provides the parallel run.
  • The synonym and blue/green ideas are dropped, because tier-2 must read real tables under their original names.
  • Legacy loading after the switch, through a shadow or backup table, is dropped. The legacy table is frozen at D-1 and rollback uses catch-up.
  • The research, case playbooks and strategy pages still stand as background.
